# Position — Niko Matsakis (Rust language co-lead; salsa creator)

**Verdict:** KEEP_WASM
**Confidence:** 4

## Arguments

1. The plugin workload is a query system, and wasm guests are the only candidate whose execution model is already pure-function-shaped: linear memory, bytes in → diagnostics out, zero ambient effects. `crates/specforge-watch/src/pipeline.rs` (`apply_invalidated`) and `dispatch.rs` (`plan_incremental_dispatch`) hand-roll exactly the invalidation layer that should become red-green memoized queries over plugin results. That evolution needs R-6 determinism; interpreter embeds (CPython/V8 gc, time, randomness) erode purity at the edges. Wasm execution is deterministic by construction — snapshots stay honest forever.
2. R-1 kills MULTI on the record: C7-11 documents three parallel implementations as today's disease. A scripting tier recreates it, multiplying protocol and audit surface. One mechanism — the one already behind 3,070 green tests.
3. C7-02 (AOT cache is a byte-copy) and C7-08 (EnginePool is a ledger) are unbuilt infrastructure, not a verdict on the model. rustc/salsa lesson: you don't abandon the computation model because the caching tier is vaporware; you build it. Wasm blobs also satisfy R-4 reproducibly — compile once, hash, sign; `.py`/`.ts` behavior varies per interpreter version. The authoring tax is prepaid: guests total 629 LOC, ~97% generated by SDK macros.

## Biggest risk in my verdict

Authoring ergonomics. Requiring a Rust toolchain + `wasm32-unknown-unknown` may starve the third-party registry bet, and capability-scoped IO over Extism imports is clunky if plugins genuinely need ambient access (collectors hint at this).

## What would change my mind

Evidence of a real author population that cannot pay the Rust toolchain tax, plus a Lua/TS embed demonstrating capability-scoped IO, snapshot-deterministic output, and wasmtime-competitive cold start; or proof the C7-03 IDL gap is unfixable over `call_export`.
