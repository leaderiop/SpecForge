gsd-core/workflows/verify-work.md	Resolve whether the secure-phase step hook is enabled: an entry with `kind == "step"` and `ref.skill == "secure-phase"` present in `activeHooks` OR `skippedHooks` of `VERIFY_POST_HOOKS_JSON` both count as enabled. `--after-fingerprint` moves this hook into `skippedHooks` once the phase already has its declared artifact (`SECURITY.md`, the phase's `security_audit`; #5105) — the hook is still enabled, only its re-dispatch is skipped. prompt:extract_learnings	Each learning is a `lesson` entity in `spec/lessons.spec`, written with `specforge new lesson`; its `kind` is the category (`decision`, `lesson`, `pattern` or `surprise`), and `specforge check` checks it like any entity. A `lesson` has no phase field and no counts: its id (`L-<phase>-<n>`) carries the phase, and the counts are the lessons of each kind. `LEARNINGS.md` is not written. Nothing here removes a lesson: if an earlier run of the phase recorded more lessons than this one, name the extra ids to the user.
prompt:workspace	A workspace is a directory of git worktrees or clones beside this project, with a `WORKSPACE.md` that the agent writes: it is another checkout, so the spec does not model it and there is no `init.*-workspace` query. The text above does its work with the shell (`ls`, `git worktree list`). A new workspace gets its own spec: `specforge init`, `specforge add @gsd/core`, then `specforge install <host>` in the workspace directory.
