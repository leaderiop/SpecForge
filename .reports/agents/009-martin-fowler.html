Evidencecrates/specforge-migrate/src/lib.rs:23-29,176-186 — MIN=CUR=MAX=1.0; transform_content only rewrites the header; migration hooks exist (MigrationHookRunner, timeout/trap handling)crates/:- — detect_format_version is referenced only by specforge-migrate itself and cli/migrate.rs — the compile pipeline (emitter/compile.rs) never checks a file's declared version, so E015 'unsupported format version' can never fire during specforge check

specforge-migrate has genuinely good scaffolding: ordered FormatVersion, MIN=CUR=MAX 1.0 constants, detect_format_version emitting E015 on unparseable headers, and MigrationHookRunner machinery with timeout handling. But detect_format_version is referenced only inside specforge-migrate and cli/migrate.rs — the normal compile pipeline never inspects a declared version, so a file stamped specforge-format 99.0 compiles without complaint under specforge check and E015 can only fire when the user runs migrate. Wire the version check into graph build so E015 and I007 surface alongside parse diagnostics, and add a per-version changelog table so v1.1 has a defined migration path before the first breaking change.

// Wire the format stamp into the normal compile pipeline.
use specforge_migrate::{detect_format_version, CURRENT_FORMAT_VERSION, MAX_SUPPORTED_VERSION};

fn check_format_headers(spec_files: &[SpecFile], diags: &mut Vec<Diagnostic>) {
    for file in spec_files {
        let (version, mut d) = detect_format_version(&file.raw_content);
        diags.append(&mut d);
        if version > MAX_SUPPORTED_VERSION {
            diags.push(
                Diagnostic::error("E015", format!(
                    "file '{}' declares format {} newer than supported {}",
                    file.path, version, MAX_SUPPORTED_VERSION,
                ))
                .with_span(file.header_span.clone())
                .with_suggestion(format!(
                    "downgrade with: specforge migrate --to {CURRENT_FORMAT_VERSION}"
                )),
            );
        } else if version < CURRENT_FORMAT_VERSION {
            diags.push(Diagnostic::info("I007", format!(
                "file '{}' uses older format {}; run `specforge migrate`",
                file.path, version,
            )));
        }
    }
}

Explain like I'm 10

The house has a beautiful doorbell system, but it is not wired to the front door: a file stamped with a future version 2.0 walks straight into the compiler unchallenged, and only the moving crew (migrate) ever reads the stamp. Wire the stamp check into the normal compile so old/new files are detected where users actually work.

Proposed solution. Have the compile pipeline call detect_format_version per file and surface E015/I007 alongside parse diagnostics; add a changelog-per-version table (Fowler's migration guidance) so v1.1 has a defined path before the first breaking change lands.
