The fix is to load the cached schema, diff it against the freshly generated one, bump via compute_schema_version, and negotiate over the (cached, current) pair.

SchemaVersion Ord (schema.rs:72-83) ignores label: 1.0.0-beta == 1.0.0 ordering while Eq differs; semver says beta < release.

mediumC6-03
037 Henry Andrewseffort Smoves: negotiation
Evidenceschema.rs:72-83

SchemaVersion derives PartialEq/Eq over all fields including label, but the manual Ord impl (schema.rs:72-79) compares only major/minor/patch. Per semver, 1.0.0-beta must sort strictly below 1.0.0; here cmp returns Ordering::Equal for the pair while Eq says they differ, violating the Ord/PartialEq consistency contract that sorted containers (BTreeMap, sort) rely on. In a schema cache keyed or deduped by version, two distinct versions can collide in ordering, making 'latest' resolution ambiguous. The fix is to make label participate: None (release) sorts above Some(_), and two labels compare lexically.

impl Ord for SchemaVersion {
    fn cmp(&self, other: &Self) -> Ordering {
        self.major.cmp(&other.major)
            .then(self.minor.cmp(&other.minor))
            .then(self.patch.cmp(&other.patch))
            // semver: a pre-release sorts BELOW the release;
            // release (None) > pre-release (Some), labels compare lexically.
            .then(match (&self.label, &other.label) {
                (None, None) => Ordering::Equal,
                (None, Some(_)) => Ordering::Greater,
                (Some(_), None) => Ordering::Less,
                (Some(a), Some(b)) => a.cmp(b),
            })
    }
}
