The repo publishes report schemas (the vision calls the Graph Protocol schema the product) but nothing validates against them: no test reads the schema files, no JSON Schema validator dependency exists, and nothing consumes the written per-binary json. With additionalProperties:false, adding a field to TestRecordEntry (as C11-07 proposes) makes all previously-valid reports invalid and no test would notice - conformance is a human eyeballing JSON. For an ecosystem play, the producer being unvalidated removes the reference-implementation guarantee; one test serializing a real BinaryReport and validating it turns drift into a red CI run.

#[test]
fn serialized_report_conforms_to_binary_report_schema() {
    let entries = vec![TestRecordEntry {
        entity_kind: "behavior".into(),
        entity_id: "create_user".into(),
        test_name: "create_user_contract".into(),
        file: "tests/contracts.rs".into(),
        verify: Some("creates a user with valid input".into()),
        verify_kind: Some("unit".into()),
        outcome: TestOutcome::Pass,
    }];
    let json = serde_json::to_string(&report::build_ref("1.0", "contracts", &entries)).unwrap();

    let schema: serde_json::Value =
        serde_json::from_str(include_str!("../../../schemas/binary-report.schema.json")).unwrap();
    let validator = jsonschema::validator_for(&schema).unwrap();

    // additionalProperties: false means any struct/schema drift fails HERE,
    // in CI, not silently in a user's pipeline.
    let value = serde_json::from_str(&json).unwrap();
    assert!(
        validator.is_valid(&value),
        "BinaryReport serialization drifted from schema: {json}"
    );
}
