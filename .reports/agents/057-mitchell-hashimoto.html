Auditor review

The registry abstraction is genuinely nice — find_registry_for_specifier routing, typed errors with guidance, a hash-pinning lockfile — but publish never loads the credential login stored, so every publish 401s. Fix the auth wiring first, then make store-then-insert atomic since racers rewrite immutable blobs, and prove it with a mock-registry test asserting 201 on an authorized publish.

Explain like I'm 10

You made a key that unlocks the door and put it safely in your pocket — but when you deliver the package, you never take the key out. Every publish knocks on a locked door and is turned away. The login and publish features were built separately and never introduced.

Proposed solution. Load the CredentialStore for the routed registry in publish.rs/publish_to_registry, resolve the token, and have HttpRegistryClient::publish accept an optional bearer token and set AUTHORIZATION. Integration-test against a mock server (201 on authorized publish).

flowchart TD
 A[store blob first] --> B[insert row]
 B --> C[UNIQUE conflict leaves orphan blob]
 D[racer] --> E[fs write truncates blob]
 E --> F[hash mismatch on disk]

Explain like I'm 10

Two librarians glance at the same empty shelf at the same time and both file their copy in the same slot; one silently replaces the other and the label no longer matches the contents. Write the label first, and never rewrite a slot that already has a book.

Proposed solution. INSERT first (UNIQUE(name,version) already serializes), then store_wasm, deleting the blob on failure; use create-new semantics so existing artifacts are never overwritten.
