Auditor review

Samuel Colvin (pydantic): Validation that fails open is my biggest pet peeve, and this engine fails open three ways: malformed regex means no violation, register_custom_patterns registers patterns whose probe traps, and both call-sites pass None for the Wasm runtime so custom validators can literally never fire. Wire CompositeRuntime in, compile regexes and check values at parse time, emit W-codes for misconfiguration. A rule that silently never runs is worse than no rule.

Misconfigured rules fail silent: malformed regex -> no violation (validation_engine.rs:218-235); register_custom_patterns accepts Ok OR Err (326-358);

Evidencevalidation_engine.rs:218-235

Misconfigured rules fail open everywhere: a malformed regex in a matches constraint compiles per entity and Err(_) => false treats the bad pattern as no-violation (validation_engine.rs:227-230); register_custom_patterns (validation_engine.rs:331-358) matches Ok(_) | Err(_) and registers the pattern either way, so a wasm function that traps on the __probe__ call is indistinguishable from a healthy one; one_of with an empty values list never matches anything, and missing field/constraint combos silently return false. A rule that can never fire is worse than no rule — it gives authors false confidence, like a smoke detector with a dead battery. Parse-time validation in parse_rule_pattern (compile the regex once, check field names against the field registry, require non-empty values for one_of) would surface W-code diagnostics at authoring time instead.
