Model DOT hardcodes palette instead of declared per-kind colors

Evidencecrates/specforge-emitter/src/model/dot.rs:7-13 — COLOR_* matched by extension name; per-kind dot_color ignoredcrates/specforge-emitter/src/outline/dot.rs:57-62 — color via substring contains match

model/dot.rs maps extension NAME to a hardcoded 5-color palette (COLOR_SOFTWARE etc.), ignoring per-kind dot_color stored in the registry; outline/dot.rs is worse — extension_color does a substring name.contains(key) match, so an extension named 'governance-tools-plus' gets the governance color. One color per extension means the map legend colors the whole country one shade. Fix: resolve per-kind color from the registry with extension as fallback, exact match not substring.

fn kind_color(kind: &str, registry: &KindRegistry, extension: &str) -> String {
    if let Some(entry) = registry.get(kind) {
        if let Some(color) = &entry.dot_color {
            return color.clone();
        }
    }
    extension_color(extension).to_string()
}

fn extension_color(name: &str) -> &str {
    match name {
        "@specforge/software" => COLOR_SOFTWARE,
        "@specforge/product" => COLOR_PRODUCT,
        "@specforge/governance" => COLOR_GOVERNANCE,
        "@specforge/formal" => COLOR_FORMAL,
        _ => COLOR_FALLBACK,
    }
}
