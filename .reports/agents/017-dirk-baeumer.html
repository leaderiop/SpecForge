LSP positions treated as byte offsets.

highC4-02
017 Dirk Bäumereffort M
Evidencedocument.rs:90-97

DocumentBuffer::line_col_to_offset treats LSP character as a byte offset while clients send UTF-16 units, so non-ASCII text earlier on the line misplaces did_change ranges, hover/completion positions, and tree-sitter InputEdit points. One position codec (or utf-8 negotiation) plus a non-ASCII regression test fixes the class.

Explain like I'm 10

The editor counts letters one way (a smiley counts as 2) and the server counts another way (as 1). After you type a smiley, the server points at the wrong word. Both must agree on one counting rule.

Proposed solution. one position codec on DocumentBuffer or negotiate utf-8 encoding; add non-ASCII regression test.
