Auditor review

filter_graph_by_query_scope works, compute_extension_query_scope works, and then the only live call site passes QueryScope::All unconditionally — a plugin declaring query_scope own still gets the whole graph. That is a capability-control gap dressed up as a feature, and since one shared HostContext serves all extensions there is nowhere to carry the per-plugin scope. The fix is small: a query_scope field on HostContext set from the manifest at load. I would do it the same day as the sandbox policy threading since it is the same plumbing.

Extensions declare query_scope ('all' or 'own', documented in extension-sdk.md), and the machinery exists: compute_extension_query_scope parses the manifest and filter_graph_by_query_scope correctly filters entities/edges for Own/Explicit scopes. But the live path ignores all of it — make_query_graph_fn in host_context.rs hard-codes `filter_graph_by_query_scope(&graph, &QueryScope::All)`, and since one HostContext is shared by every loaded extension there is no place to carry a per-extension scope anyway. A plugin that declared 'own' still receives the entire graph, which is both a capability-security violation and a false sense of isolation for plugin authors. Fix: give HostContext a query_scope field (or per-extension contexts) and pass compute_extension_query_scope(manifest) into the host function factory.
