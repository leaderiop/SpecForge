Auditor review

Ben Hutton (JSON Schema): The config schema is exactly how I'd teach 2020-12 bundling — $defs appendix, $ref pointers, closed objects. But your generator output would not pass my own review: fields: {type: object}, an embedded schema described as 'an object', no additionalProperties anywhere. You already hold per-kind field metadata in the registries; emitting $defs per kind with oneOf on the discriminator is mostly mechanical. Do it and the published schema stops being decorative.

Inside publish_json_schema, the embedded schema property is described only as {type: object, description: ...} (schema.rs:877-880) and node.fields is just {type: object}; nothing sets additionalProperties:false anywhere in the generated document. Every other SpecForge schema constrains tightly, so the published Graph Protocol schema accepts arbitrary garbage in the schema block and arbitrary fields on nodes — an LLM consumer validating a graph against it gets almost no guarantees beyond kind/label enums. Since generate_schema already has per-kind field lists (name, field_type, required, enum_values), per-kind subschemas in $defs selected via a kind discriminator are directly derivable.

after — proposed fix
    // Per-kind node subschemas derived from the registry field lists.
    let mut kind_defs = serde_json::Map::new();
    for k in &schema.entity_kinds {
        let mut props = serde_json::Map::new();
        let mut required = Vec::new();
        for f in &k.fields {
            props.insert(f.name.clone(), json_type_schema(&f.field_type, f));
            if f.required { required.push(Value::String(f.name.clone())); }
        }
        kind_defs.insert(k.name.clone(), serde_json::json!({
            "type": "object",
            "properties": props,
            "required": required,
            "additionalProperties": false
        }));
    }
    // nodes.items then becomes:
    // { oneOf: kind_names.map(n => ({ $ref: #/$defs/fields_<n> })) }
    // and the embedded schema block gains additionalProperties: false.
