Auditor review

Aslak Hellesoy: I split Gherkin from Cucumber so feature files could be first-class, tool-neutral evidence - and build.rs reduces test intent to has-a-verify-list, so my gherkin-linked behaviors never reach the coverage diff at all. W004 itself says verify OR gherkin; the graph exporter only reads half the rule. Export gherkin-referencing entities and bind Cucumber results via entity_id tags - then BDD teams get the same traceability matrix everyone else does.

This contradicts both W004's dual-intent model and the gherkin-bridge decision (integrations/rust/spec/decisions.spec:19-28). A pure-Cucumber team sees every behavior as NoIntent/absent and concludes coverage is broken; the gherkin field is file-reference validated, so the intent is declared but never reaches the diff.

after — proposed fix
            // W004 accepts verify OR gherkin as test intent; export both so
            // Cucumber results (tagged @specforge:entity_id) can close the loop.
            let gherkin = entity
                .fields
                .get("gherkin")
                .and_then(|v| match v {
                    FieldValue::StringList(files) if !files.is_empty() => Some(files.clone()),
                    _ => None,
                })
                .unwrap_or_default();

            let testable = !verify.is_empty() || !gherkin.is_empty();
            entities.push(ExportedEntity {
                id: entity.id.raw.to_string(),
                kind: entity.kind.raw.to_string(),
                verify,
                gherkin,
                testable,
            });
