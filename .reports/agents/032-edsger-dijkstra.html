Auditor review

Edsger W. Dijkstra: The layering instinct is real — a zero-domain graph core with vocabulary injected via GraphConfig is precisely the discipline I demand, and tests guard it. But Graph::invalidation_set is a second recipe for soup the watch crate already cooks, kept alive by an as_pairs shim; and a build script stamping wall-clock time into an otherwise deterministic artifact, with a hand-rolled calendar no less, is needless non-determinism. Delete both.

Zero-domain-knowledge core genuinely holds in the graph engine

infoC5-04
032 Edsger W. Dijkstraeffort Smoves: none (guard)

The graph core genuinely carries no domain vocabulary: every keyword, edge type, and bidirectional pair is injected via GraphConfig from extension manifests. This discipline lets one compiler serve all extensions.

exemplar — the good pattern
pub struct GraphConfig {
    /// Provider schemes that are installed (e.g., "gh", "jira").
    pub known_provider_schemes: HashSet<String>,
    /// Entity keywords registered by installed extensions (e.g., "behavior", "feature").
    pub installed_keywords: HashSet<String>,
    /// Mapping of entity keywords to the extension that provides them (full catalog).
    pub known_extension_keywords: HashMap<String, String>,
    /// Bidirectional edge pairs from extensions. Each pair (forward_label, reverse_label)
    /// represents a complementary relationship that should not be flagged as a cycle.
    pub bidirectional_pairs: Vec<(String, String)>,
}

Stamping every printout with the current time means two identical printouts never look identical — and the calendar was hand-drawn to do it. Drop the stamp, use a real date library or none.

Proposed solution. Remove the timestamp (or derive it from the newest spec file mtime) so graph.json is byte-stable; delete chrono_lite_now.
