Auditor review

An ambient agent's whole loop is notice-change-re-query, and your MCP server cannot do the first half: one compile at initialize, then a frozen snapshot, while the LSP side already has a live debounced parser you never shared. Dead notification formatters and subscribe:false in capabilities mean subscribers get protocol-honest silence. Share IncrementalPipeline with the server, diff old-vs-new on each recompile, and push graphChanged to actual subscribers - until then the graph is a photo, not a feed.

// specforge-mcp: reuse specforge-watch's IncrementalPipeline
pub fn start_watcher(state: Arc<Mutex<McpState>>, root: PathBuf, sink: Sender<Value>) {
    let mut pipeline = IncrementalPipeline::new(root);
    thread::spawn(move || {
        for event in pipeline.events() {
            let mut st = state.lock().unwrap();
            let old = st.graph.clone();
            let result = compile_project(st.project_root.as_deref().unwrap());
            st.apply_compilation(result);
            st.resource_registry_version += 1;
            for n in notifications::drain(&mut st, &old) { sink.send(n).ok(); }
        }
    });
}

Explain like I'm 10

An ambient agent subscribed to 'tell me when the spec changes' gets silence: the server takes one photo at startup and answers every question from that old photo, even as editors and CLI commands rewrite the specs. Meanwhile the LSP side already has a live camera nobody connected to the MCP server.

Proposed solution. Share specforge-watch's IncrementalPipeline (or the LSP's debounced parser) with the MCP server: recompile on change, serve updated resources, and emit specforge/graphChanged notifications to subscribers; set list_changed/subscribe capabilities truthfully once real.
