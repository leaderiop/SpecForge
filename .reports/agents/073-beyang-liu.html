fn matches_anchor(span_file: &str, query: &str) -> Option<&'static str> {
    let span = std::path::Path::new(span_file);
    let q = std::path::Path::new(query);
    if span == q {
        return Some("exact");
    }
    // Directory-prefix match on whole path components only
    if span.starts_with(q) {
        return Some("directory_prefix");
    }
    None
}

let referencing_entities: Vec<Value> = state.graph.nodes().into_iter()

Explain like I'm 10

This is a file matcher that works like Ctrl+F on paths: searching for 'task' also hands you every file with 'task' anywhere in its name. For anchoring specs to code, near-misses are worse than misses — the agent is told which entities already cover a file and may skip work because 'todo_list' matched 'todo_list_widget'.

Proposed solution. Match on path components: exact file match first, else prefix-directory match on canonicalized relative paths; return the match mode in the payload so agents know how loose the anchor is.

Code-intel primitives for specs: find_definition/references/implementation trio (praise)

infoC9-10
073 Beyang Liueffort Smoves: MCP tools exposed

The MCP surface gives agents a code-intel-style navigation trio on the spec graph itself: find_definition resolves an entity to its exact source span (file, line, column), find_references walks inbound edges, and find_implementation follows refinement edges - plus find_spec_for_source to anchor in the opposite direction. Each tool is small, typed, and returns compact JSON via content blocks, exactly the substrate models navigate code with. Shipping all four rather than describing them is what makes the specs-are-first-class-code-objects pitch real.

exemplar — the good pattern
pub fn call(state: &McpState, args: Value, id: Option<Value>) -> JsonRpcResponse {
    let entity_id = match args.get("entity_id").and_then(|v| v.as_str()) {
        Some(e) => e,
        None => return JsonRpcResponse::error(id, error_codes::INVALID_PARAMS, "Missing required parameter: entity_id"),
    };

    let node = match state.graph.node(entity_id) {
        Some(n) => n,
        None => return JsonRpcResponse::error(id, error_codes::INVALID_PARAMS, format!("Entity not found: {}", entity_id)),
    };

    let result = serde_json::json!({
        "entity_id": node.id.raw,
        "file_path": node.source_span.file,
        "line": node.source_span.start_line,
        "column": node.source_span.start_col
    });
