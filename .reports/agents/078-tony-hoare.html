Auditor review

Tony Hoare would praise the declarative, data-independent validation rules and deterministic code-sorted execution — no clever machinery. He would be blunt that a Process entity advertising initial_state and composition no check ever reads is the unverified assertion his career argued against. Fix the machine semantics first: initial_state membership is a cheap set check, not research. Until then, mark the kind experimental.

The Process entity descriptor in crates/specforge-emitter/src/builtins/formal.rs declares a rich CSP-style model — alphabet, states, initial_state, composition, sub_processes — but validation_rules() only ships W064 (orphan) and W066 (composition cycle). Nothing reads initial_state against states or checks transitions against the alphabet. A spec declaring initial_state 'closed' while states=['open'] compiles with zero diagnostics. For a tool selling machine-checked structure to AI agents, an uninterpreted state machine is decorative metadata agents wrongly trust.

The spec lets you draw machine diagrams - boxes, arrows, a start button - but the program never looks inside them. It only checks boxes are not lonely and arrows do not loop forever, like filing an org chart nobody checks against real employees.

Proposed solution. Add declarative checks (initial_state in states; participating events present in alphabet) or mark the kind experimental until event_graph_analyze exists.
