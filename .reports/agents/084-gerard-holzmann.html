Evidencecrates/specforge-emitter/src/compile.rs:478-520 — DFS inserts node when cycle_members.contains(next) after recursion - for a->b with b<->c, a is marked a cycle member though it only feeds the loop

detect_cycles' DFS does cycle_members.insert(node) whenever a recursive child ended up in cycle_members — transitively painting all DFS ancestors, not just nodes on the cycle. With a->b, b<->c, node a is reported as a W065 cycle member and the message says cycle detected involving a. Users and auto-fixing agents are pointed at an innocent node. Report SCC members only (Tarjan, already specified for E034) or reconstruct the back-edge path, and add a predecessor-into-cycle regression test.

        Some(Color::White) => {
            dfs(next, adj, color, stack, cycle_members);
            // Only propagate membership when node itself lies on the
            // back-edge path, i.e. next is still on the current DFS
            // stack. Predecessors that merely feed the cycle are NOT
            // cycle members.
            if stack.contains(&next) {
                cycle_members.insert(node);
