specforge-watch/src/pipeline.rs rebuild() calls parse(&content, file) — the non-incremental wrapper that passes None as the old tree — for every invalidated file, then clones every cached SpecFile out of parsed_files via values().cloned() and reruns build_graph over the entire corpus on every cycle. The incremental machinery exists and is exercised: parse_incremental takes Option<&Tree> and the LSP backend stores/returns previous_tree per document. The daemon never wired it up: no previous Tree is retained per file, and the SpecFile clone loop means O(corpus) work per keystroke-scale event even when the import-DAG invalidation correctly shrank the re-parse set. Storing Tree alongside SpecFile per file and splicing only changed entities (the deltas are already computed via compute_graph_delta_with_config) would make watch O(changed) end to end.

struct ParsedFile {
    spec_file: SpecFile,
    /// Previous tree, fed back into parse_incremental on the next edit.
    tree: Option<tree_sitter::Tree>,
}

impl WatchPipeline {
    pub fn rebuild<F>(&mut self, changed_files: &[String], read_file: F) -> IncrementalResult
    where F: Fn(&str) -> Option<String>,
    {
        let old_graph = self.graph.clone();
        let invalidation_set = self.import_dag.invalidation_set(changed_files);

        for file in &invalidation_set {
            match read_file(file) {
                Some(content) => {
                    let old_tree =
                        self.parsed_files.get(file).and_then(|p| p.tree.as_ref());
                    let (spec_file, tree) =
                        specforge_parser::parse_incremental(&content, file, old_tree);
                    let imports: Vec<String> = spec_file
                        .imports
                        .iter()
                        .map(|i| i.path.to_string())
                        .collect();
                    self.import_dag.set_imports_resolved(file, imports);
                    self.parsed_files.insert(
                        file.clone(),
                        ParsedFile { spec_file, tree },
                    );
                    rebuilt_files.push(file.clone());
                }
                None => {
                    self.parsed_files.remove(file);
                    self.import_dag.remove_file(file);
                    rebuilt_files.push(file.clone());
                }
            }
        }
        // ... splice rebuilt files into self.graph instead of cloning the
        // whole corpus through build_graph; fall back to full rebuild only
        // when import edges changed.
    }
}

LSP InputEdit treats UTF-16 columns as raw offsets — corrupts on non-ASCII

highC3-09
015 Björn Linse (bfredl)effort Mmoves: Adoption
Evidencelsp/document.rs:40-88 — byte offset = line start + raw column, but LSP columns are UTF-16; multibyte chars misalign tree.edit vs replace_rangelsp/backend.rs:845-853 — debounced path reuses mis-edited tree — silent wrong node reuse

DocumentBuffer::apply_change treats LSP positions as raw byte/char offsets: line_col_to_offset returns line_start_offset + col, but the LSP protocol specifies UTF-16 code units. After any character above U+FFFF (emoji, CJK extension) — or any astral-plane char earlier on the line — start_offset lands mid-character or past the intended column, so content.replace_range panics on a char boundary or silently edits the wrong span. Worse, the tree.edit InputEdit uses the same bogus positions with Point.column equal to the UTF-16 column, so the cached tree and the mutated text disagree; the debounced path in backend.rs then calls parse_incremental with that mis-edited tree and tree-sitter happily reuses stale nodes, producing a parse that succeeds but is quietly wrong. The fix is to convert UTF-16 columns to byte offsets by walking the line's chars (1 unit for BMP, 2 for astral), plus a regression test editing after an emoji.

    /// Convert an LSP (line, utf16 col) pair to a byte offset.
    /// LSP positions are UTF-16 code units; naive `offset + col`
    /// misaligns after any astral-plane character (emoji, CJK ext).
    fn line_col_to_offset(&self, line: usize, col: usize) -> usize {
        let mut offset = 0;
        for (i, l) in self.content.split('
').enumerate() {
            if i == line {
                let mut units = 0usize;
                for (byte_off, ch) in l.char_indices() {
                    if units >= col {
                        return offset + byte_off;
                    }
                    units += ch.len_utf16();
                }
                return offset + l.len(); // end of line
            }
            offset += l.len() + 1; // +1 for '
'
        }
        self.content.len()
    }

    // Also derive tree_sitter::Point columns from char_indices counted in
    // UTF-16 units, so tree.edit positions match the re-encoded text.
    // Regression test: insert ASCII after "\u{1f600}" on the same line and
    // assert the reparsed tree's node text matches the buffer.
