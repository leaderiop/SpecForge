Auditor review

max_execution_ms 30 seconds is a speed limit with no police, and the single plugins.lock() held across plugin.call means one slow extension stalls every other one — in an LSP process that is a frozen IDE. The lock-free refactor (per-extension Arc<Mutex<LoadedPlugin>>) is easy; the epoch-interruption wiring needs a bit of wasmtime care but Extism exposes the engine. Together they turn 'extensions cannot hang your compiler' from aspiration to property, and the epoch trap gives you a proper typed error to report.

max_execution_ms defaults to 30_000 in default_sandbox_policy but is never read at runtime, and call_export holds the single plugins Mutex across the whole plugin.call so one slow plugin serializes every extension indefinitely. Fix: enforce the limit with wasmtime epoch interruption and switch to per-extension locks so extensions run concurrently.

    fn call_export(&self, extension_name: &str, export_name: &str, input: &[u8]) -> WasmCallResult {
        // Per-extension lock: one slow plugin no longer serializes the others.
        let entry = self.plugins.lock().ok()?.get(extension_name).cloned()?;
        let _guard = entry.lock().ok()?;

        // Enforce max_execution_ms via wasmtime epoch interruption.
        let ms = self.policy.max_execution_ms.unwrap_or(30_000) as u64;
        let epoch = self.engine.epoch_deadline(ms);
        let result = entry.plugin.call::<&[u8], Vec<u8>>(export_name, input);
        drop(epoch);
        match result {
            Ok(output) => WasmCallResult::Ok(output),
            Err(e) => WasmCallResult::Trap(WasmTrapInfo {
                kind: "execution_timeout".into(),
                message: format!("extension '{extension_name}' exceeded max_execution_ms: {e}"),
                export_name: export_name.into(),
            }),
        }
    }
