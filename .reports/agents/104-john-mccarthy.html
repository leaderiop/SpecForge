CBCL violation: one concept, two formal spellings — `extension` in the compiled root, `package` in every doc example

CBCL violation: the compiled root (spec/specforge.spec:15) writes the provider field as extension "@specforge/gh", while every documentation example (docs/extension-model.md:88-116, five instances) and the field-table docs (docs/entities/spec.md:151) spell it package "@specforge/gh". One of the two cannot parse against the real grammar — agents that copy the doc syntax will hit parse errors against the compiled form, and the two spellings break the one-concept-one-name discipline the whole project is built on. The provider example also points at a nonexistent upstream (anthropics/specforge), compounding the counterfactual. Pick the grammar's spelling, migrate the loser, and emit a migration diagnostic.
