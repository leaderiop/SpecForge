// tools/schema.rs - derive the input schema from the handler's arg struct
#[derive(Deserialize, JsonSchema)]
pub struct QueryArgs {
    pub entity_id: String,
    #[serde(default = "default_depth")]
    pub depth: usize,
    #[serde(default)]
    pub include_coverage: bool,
    #[serde(default)]
    pub kinds: Vec<String>,
}

pub fn query_input_schema() -> Value {
    serde_json::to_value(schemar::schema_for!(QueryArgs)).unwrap()
}
// registry builds descriptors from this; dispatch deserializes QueryArgs so a
// schema/handler mismatch cannot compile. Test asserts each dispatch arm's
// required params match the handler's first-failure behavior.

The menu and the kitchen disagree: the menu (tool schema the agent reads) omits dishes the kitchen actually makes (format, include_coverage) and lists none of the size options. A typed-contract shop can't afford hand-written menus that rot — agents order from the menu, so undocumented capability is invisible capability, and undocumented drift is worse.

Proposed solution. Derive input schemas from a single typed Rust description (serde-schemars or a small macro over handler arg structs) so descriptor and handler cannot diverge; add a test that every dispatch arm in tools/mod.rs has a registry entry whose required params match the handler's first-failure behavior.
