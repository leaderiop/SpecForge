get_plan puts the full unanalyzed_files path list straight into the prompt payload with no cap, so on a 2,000-file repo the model's window absorbs ~2,000 paths just so it can pick the first ten to process - prompt size grows linearly with repo size instead of staying bounded. stale_files has the same problem. The instruction even tells the model to process files with the most entity signals first, which requires ranking the model could do far more cheaply from a capped top-N plus a count. infer_session/infer_progress already track per-file progress, so a cursor for paging the remainder is a natural fit.

Explain like I'm 10

Asking for a study plan and getting a phone book: on a 2,000-file repo the plan prompt would dump all 2,000 paths into the model's window just so it can pick the first ten. The query tool already knows how to zoom; the plan prompt forgot to.

Proposed solution. Cap unanalyzed_files to the top N by kind priority/size with a '...and K more' marker plus a follow-up cursor (infer_progress already tracks files), so the plan prompt stays roughly constant-size.
