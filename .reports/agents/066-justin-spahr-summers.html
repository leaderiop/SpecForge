Subscription and notification machinery is dead scaffolding

highC9-01
066 Justin Spahr-Summerseffort Mmoves: subscription capability actually servable

notifications.rs ships a full delta/notify stack: compute_graph_delta, compute_diagnostics_delta, and formatters for specforge/graphChanged and specforge/diagnosticsChanged. But pending_notifications diffs the live graph against a freshly constructed empty Graph::new(), so every startup reports the entire graph as added, and nothing ever calls this function on recompile - there is no watcher thread, and lifecycle.rs compiles exactly once during initialize. Subscriptions (resources/subscribe) have no handler in protocol/router.rs, and McpCapabilities advertises subscribe:false, list_changed:false. For a server pitched as an agent's live view of the spec, change events are the core loop and they are entirely inert.

pub fn pending_notifications(state: &mut McpState) -> Vec<Value> {
    let mut notifications = Vec::new();

    let graph_delta = compute_graph_delta(&Graph::new(), &state.graph);
    if !graph_delta.added_nodes.is_empty() || !graph_delta.removed_nodes.is_empty() {
        notifications.push(format_graph_notification(&graph_delta));
        state.push_event("mcp_delta_notified", serde_json::json!({"kind": "graph"}));
    }

    let diag_delta = compute_diagnostics_delta(&state.previous_diagnostics, &state.diagnostics);
    if !diag_delta.added.is_empty() || !diag_delta.removed.is_empty() {
        notifications.push(format_diagnostics_notification(&diag_delta));
        state.push_event("mcp_delta_notified", serde_json::json!({"kind": "diagnostics"}));
    }

    notifications
}

// Driven by specforge-watch's IncrementalPipeline on every recompile
pub fn drain_notifications(state: &mut McpState, old: &Graph, old_diags: &[Diagnostic]) -> Vec<Value> {
    let mut notifications = Vec::new();

    let graph_delta = compute_graph_delta(old, &state.graph);
    if !graph_delta.is_empty() {
        notifications.push(format_graph_notification(&graph_delta));
        notify_subscribers(state, "specforge/graphChanged", &graph_delta);
    }

    let diag_delta = compute_diagnostics_delta(old_diags, &state.diagnostics);
    if !diag_delta.is_empty() {
        notifications.push(format_diagnostics_notification(&diag_delta));
        notify_subscribers(state, "specforge/diagnosticsChanged", &diag_delta);
    }
    notifications
}

fn notify_subscribers(state: &mut McpState, method: &str, params: &impl Serialize) {
    // state.subscriptions: uri -> subscribers, filled by resources/subscribe
    for subscriber in state.subscribers_for(method) {
        state.enqueue_frame(format_notification(subscriber, method, params));
    }
}

Explain like I'm 10

The team built a mailing list — people can sign up, and there are pre-written newsletters (graphChanged, diagnosticsChanged) — but the mailman was never hired, and the one draft newsletter compares against an empty folder so it always says 'everything is new'. Nothing bad happens, but nothing good happens either; it just looks finished.

Proposed solution. Either wire it or cut it: implement resources/subscribe + resources/list_changed, hook pending_notifications into a real old-vs-new compile comparison driven by specforge-watch, and push formatted notifications to subscribers; or delete subscriptions.rs/notifications.rs until a watcher exists.
