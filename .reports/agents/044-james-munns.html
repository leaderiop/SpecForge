The specforge-test report is plain pretty-printed JSON (serde_json::to_string_pretty, report.rs:35) — there is no binary format anywhere in the workspace: the wasm protocol bridge serializes JSON over the wire (protocol/host.rs:19-44), and Cargo.lock pulls rmp-serde via extism-convert, not postcard, so postcard is at best a transitive trace. Naming or implying a compact/binary report where a printed letter sits in the 'compact parts' box misleads consumers about size and parse cost. Either write honestly compact JSON via serde_json::to_writer into a BufWriter (no intermediate String), or actually adopt postcard behind the existing schema_version const.

    let path = dir.join(format!("{binary_name}.json"));
    let file = std::fs::File::create(&path)?;
    let mut writer = std::io::BufWriter::new(file);

    // Compact JSON straight to disk: no pretty-print buffer,
    // no intermediate String allocation.
    serde_json::to_writer(&mut writer, &report)?;
    writer.flush()?;
