Auditor review

budget.rs is genuinely good engineering - degree-centrality truncation, honest truncated_entities accounting, an error strategy for strict callers - and it is wired to nothing while context and brief, the formats agents actually consume, bypass it entirely. Default machine formats to compact serialization (to_string_pretty in brief.rs and budget.rs pays real tokens for whitespace, and budget.rs re-serializes pretty on every loop iteration, inflating its own estimates). Fix the gate to cover all three JSON formats, surface --max-tokens on CLI and MCP, and put a paging hint in the budget metadata.

Token budget is Json-only and wired to nothing — context/brief are unbudgeted

highC9-03
068 Paul Gauthiereffort Mmoves: formats honoring token_budget in emitter

budget.rs implements a real degree-centrality truncation algorithm with a TokenBudgetResult listing truncated_entities, but emit.rs applies it only when format == EmitFormat::Json - the agent-optimized Context and Brief formats are emitted at unlimited size regardless of token_budget. No caller ever sets token_budget anyway: CLI export.rs passes token_budget: None unconditionally, and the MCP export/query tools never read a max_tokens argument, so the feature is unreachable from every surface. Additionally the truncation metadata is only embedded in JSON output, so even a hypothetical Context export could not tell an agent what was dropped or how to fetch it. The result is a tested token-budget engine wired to nothing.

Explain like I'm 10

Someone built a very good suitcase that shrinks to fit the overhead-bin limit — tested, with a label listing what got left out. But no door of the airport actually lets you carry it: the check-in desk (CLI) and the gate (MCP tool) never hand it to you. Meanwhile the 'context-optimized' bags are packed without any size limit at all.

Proposed solution. Extend the budget gate to Context and Brief in emit.rs, add --max-tokens to CLI export and max_tokens to the MCP export tool, and make the budget metadata (truncated_entities) part of context/brief payloads so agents can page in the remainder via query.

Machine formats are pretty-printed, burning tokens on whitespace

mediumC9-04
068 Paul Gauthiereffort Smoves: formats honoring token_budget in emitter

emit_brief ends with serde_json::to_string_pretty, so the minimal id/kind/title format - whose entire purpose is minimizing tokens - is indented across multiple lines per entity, roughly doubling token cost on nested JSON where every newline and indent is billed. The same pattern holds in budget.rs, which also serializes pretty on every truncation-loop iteration, inflating its own token estimates. For a product whose pitch is token efficiency, machine formats should be compact by default with an explicit human opt-in. The fix is one method name plus a --pretty flag on the export surfaces.

Explain like I'm 10

Brief is the 'smallest possible summary' format, yet it's printed like a document for humans — every line indented, every brace on its own line. For a model, all that indentation is paid-for tokens that carry zero meaning, roughly doubling the bill on deeply nested JSON.

Proposed solution. Default json/context/brief to compact serialization (to_string), keep a --pretty flag for humans; add a snapshot test asserting brief output per entity shrinks vs compact-context.
