Christoph Nakazawa: your report schema promises skip/error/duration_ms/message and your code can produce none of them - and should_panic tests, the most common Rust test idiom after happy path, get recorded as Fail because the guard equates panicking with failing. The invariant documents the bug and the macro ships anyway; detect should_panic in the expansion and invert the outcome. Until then coverage numbers are wrong for a whole category of tests, and wrong numbers are worse than no numbers.

TestGuard::drop maps thread::panicking() to Fail unconditionally, so #[should_panic] tests - where panic is the success path - record Fail in the registry, report, and coverage diff (only Pass counts toward passing). spec/invariants.spec:81-90 documents should_panic_incompatibility and requires the macro to emit a compile-time warning, but specforge-test-macros/src/lib.rs forwards attrs blindly (#(#attrs)*) and never checks for should_panic. The report schema's skip/error/duration_ms/message are unproducible: TestOutcome has only Pass/Fail with no timing or panic-message capture, so expected-panic tests drag entities to CoveredWithFailures and skips look never-run.

impl Drop for TestGuard {
    fn drop(&mut self) {
        let expected_panic = self.should_panic && std::thread::panicking();
        let outcome = if std::thread::panicking() && !expected_panic {
            TestOutcome::Fail
        } else {
            TestOutcome::Pass
        };

        registry::record(TestRecordEntry {
            entity_kind: self.entity_kind.to_string(),
            entity_id: self.entity_id.to_string(),
            test_name: self.test_name.to_string(),
            file: self.file.to_string(),
            verify: self.verify.map(|s| s.to_string()),
            outcome,
            duration_ms: Some(self.start.elapsed().as_millis() as u64),
            message: std::thread::panicking().then(|| self.panic_message.clone()),
        });
    }
}
