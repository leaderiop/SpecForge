JsonGraphV2, ContextGraphV2 and BriefGraphV2 all embed schema: GraphProtocolSchema by clone (schema.rs:355-365 and each emit_* body), and the scoped wrappers emit_*_scoped_with_schema (schema.rs:762-800) pass the full schema along to the subgraph export. For a brief export of one entity, the embedded schema (all kinds, all edges, all fields, plus extension info) can dwarf the payload by orders of magnitude — the whole phone book taped into every letter. SchemaCacheEntry already carries a content_hash (schema.rs:207-210), so a schema_ref: {url, content_hash} option referencing the published schema is cheap to add; embedding should become opt-in for scoped exports.

write_report (integrations/rust/specforge-test/src/report.rs:34-36) writes the JSON straight to the final path with std::fs::write, while persist_schema_cache in the same workspace already does the temp-file-plus-rename dance (schema.rs:687-691). A crash or full disk mid-write leaves a truncated or half-old/half-new {binary_name}.json that consumers of the test report will parse as corrupt. The fix is two lines: write to a dotfile sibling and rename over the target, matching the existing project idiom.

    let path = dir.join(format!("{binary_name}.json"));

    std::fs::write(&tmp, &json)?;
    std::fs::rename(&tmp, &path)
