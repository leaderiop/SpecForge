format/fields/group_by flags are free Strings; clap cannot reject typos or offer value completions

mediumC14-10
122 Kevin Knappeffort Mmoves: CLI flags type-validated (warn to good)
Evidencecrates/specforge-cli/src/main.rs:46-79 — Every format-ish flag (format, fields, group_by, deps, collector) is a free String with default_value, about 30 occurrences. Validation happens later by runtime string match (export.rs parse_format, outline.rs). An invalid value like jsn is a runtime error with no clap blame, and shell completions cannot offer values.

In crates/specforge-cli/src/main.rs roughly thirty format-ish flags (format, fields, group_by, deps, collector, lint) are free Strings with default_value; the real vocabularies (human|json, markdown|mermaid|dot|json|dbml, none|keys|all, direct|effective|full) are enforced later by runtime string matching in export.rs parse_format, model.rs, outline.rs. A typo like --format jsn is a bespoke runtime error with no clap blame pointing at the flag, and clap_complete-generated completions cannot offer values. clap ValueEnum types (OutputFormat, FieldLevel, GroupBy, DepsLevel) make the accepted sets machine-checked at parse time and exhaustively matchable downstream.
