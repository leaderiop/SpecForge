Auditor review

This is the classic same-channel integrity trap: the hash comes from the server that served the bytes, so it catches bit-rot and nothing else, and with no metadata expiry rollback is free. The good news is LockFileEntry already pins wasm_hash — exactly the offline anchor a TUF-style design needs. Add publisher-signed targets with expiry, verify at add and upgrade, and the lockfile becomes the trust root the registry cannot rewrite.

pub fn verify_signed_targets(entry: &LockFileEntry, root: &RootMetadata, wasm: &[u8])
    -> Result<(), Diagnostic>
{
    let st = entry.signed_targets.as_ref().ok_or_else(|| missing_targets_diag())?;
    check_not_expired(&st.expires)?;
    let key = root.keys.get(&st.key_id).ok_or_else(|| unknown_key_diag(&st.key_id))?;

    verify_ed25519(key, &format!("{}|{}|{}", entry.name, entry.version, digest), &st.signature)

}

Explain like I'm 10

Checking the food's seal against the label on the same box catches a crushed box in transit, but is useless if the whole box was swapped — the forger prints a matching label too. Real safety needs a dated label from someone else you trust, pinned where the registry can't touch it.

Proposed solution. TUF-style signed root/targets metadata per registry: publisher-signed target digests verified in add/upgrade, metadata expiry for freshness, digests recorded in the lockfile as the offline anchor. A minimal publisher-signed-manifest step closes the same-channel hole.
