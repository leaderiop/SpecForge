Two fixes stand between this registry and multi-tenant disaster. First, token_has_scope is a raw starts_with — a badge for org/soft opens the org/software door; make the boundary exact up to a slash and unit-test the sibling prefix. Second, there is zero artifact signing anywhere and publisher is just a token label, so the operator is the entire root of trust — an ed25519 detached signature over the digest at publish, verified at install, is the minimal MVP that survives a registry compromise.

pub fn token_has_scope(record: &TokenRecord, package_name: &str) -> bool {
    match &record.scope {
        None => true,
        Some(scope) => {
            package_name == scope
                || package_name
                    .strip_prefix(scope.as_str())
                    .is_some_and(|rest| rest.starts_with('/'))
        }
    }
}

pub fn verify_artifact(data: &[u8], manifest: &ManifestV2, keys: &HashMap<String, Ed25519PublicKey>)
    -> Result<(), Diagnostic> {
    verify_registry_integrity(data, &hex_sha256(data))?;
    if let Some(sig) = &manifest.signature {
        keys.get(&sig.key_id).ok_or_else(|| unknown_key_diag(&sig.key_id))?
            .verify(data, &sig.signature).map_err(|_| bad_signature_diag())?;
    }
    Ok(())
}

Explain like I'm 10

Anyone who knows the mailroom password can send packages that look like they came from you — no wax seal, no verifiable return address. A 'seal it with a click' system (sign with your login, verify on install) proves packages really came from the publisher even if the mailroom is robbed.

Proposed solution. Optional signature on publish (client signs wasm digest with an OIDC-issued or local key), persisted in the packages table; extend integrity.rs to verify digest-then-signature when present. Sigstore/cosign blob signing is the reference UX; an ed25519 detached-signature MVP beats nothing.
