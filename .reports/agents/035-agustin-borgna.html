Bidirectional-pair suppression is string-based, 2-hop only, and blind to longer complementary cycles

mediumC5-08
035 Agustín Borgna (ABorgna)effort Mmoves: Cycle-detection implementations (merges into shared SCC)

Bidirectional-pair suppression only handles exact 2-hop cycles and compares labels via as_str() against Vec<(String,String)>, so a 3-hop chain of complementary pairs is falsely reported as W061. Intern pairs into HashSet<(Sym,Sym)> and suppress at SCC level: an SCC is a false positive iff removing paired edges breaks its strong connectivity.

    // In Graph struct: interned complementary pairs, both orientations.
    bidirectional_pairs: HashSet<(Sym, Sym)>,

    /// True iff removing all edges whose labels participate in a
    /// complementary pair breaks this SCC's strong connectivity.
    fn is_complementary_scc(&self, scc: &[Sym]) -> bool {
        let member: HashSet<Sym> = scc.iter().copied().collect();
        // Keep only non-paired edges inside the SCC.
        let edges_from: HashMap<Sym, Vec<Sym>> = self.edges.iter()
            .filter(|e| member.contains(&e.source) && member.contains(&e.target))
            .filter(|e| !self.paired_labels.contains(&(e.label, e.label)))
            .fold(HashMap::new(), |mut m, e| {
                m.entry(e.source).or_default().push(e.target); m
            });
        // SCC-level check: iterative forward and backward reachability
        // from scc[0]; both must cover all members.
        let reach = |forward: bool| -> usize { /* BFS over edges_from or its reverse */ };
        reach(true) == scc.len() && reach(false) == scc.len()
    }

Explain like I'm 10

The rule 'asking and answering each other isn't a fight' only works when it's exactly one question and one answer. Ask, answer, ask back through a friend — the referee blows the whistle anyway. And the referee reads the names out letter-by-letter instead of recognizing them.

Proposed solution. Intern pairs into a HashSet<(Sym, Sym)> (Sym is already the currency of the crate), and run suppression at SCC level: an SCC is a false positive iff every edge in it participates in a complementary pair (i.e., removing paired edges breaks the SCC) — naturally handles chains of any length.

# ADR 0004: Hand-rolled graph storage vs petgraph

## Decision
Keep hand-rolled storage until a CI criterion bench (graph_scale)
trips any threshold at 10x corpus (21k entities):

- graph build exceeds 250 ms
- detect_cycles exceeds 25 ms
- node/edge removal dominates watch-mode profiles

## Consequences
- petgraph adoption (StableGraph, toposort, SCC) is pre-approved once
  a threshold trips; no new ADR required.
- The linear-time claim stays measured, not assumed.
