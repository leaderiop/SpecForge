Phase 0 of the canonical authoring walkthrough asks for an ID infix, invents a plugins spec field, and lists providers @specforge/gh/jira/figma as if installed; Phase 1 writes deliverable IDs as DLV-{infix}-{n}. The real binary has no infix concept (Init takes --extensions in crates/specforge-cli/src/main.rs), the field is extensions, and only registered ref schemes resolve. A newcomer executing the tutorial command-by-command hits failures the manual itself manufactured. The doc should be executable: every snippet runs through specforge check in CI, infix/DLV prefixes dropped, unregistered providers marked roadmap.

The tutorial is teaching the old model of the product — like a driving manual that still explains hand-crank starting. New users copy the tutorial verbatim and get errors for things the manual invented. The walkthrough must be executed command-by-command against the real binary before it ships.

Proposed solution. Rewrite spec-writing-flow.md executing every snippet via `specforge check` in CI (docs-as-tests, TRPL model). Drop infix/DLV prefixes; rename plugins→extensions; point providers at actually registered schemes or mark @specforge/gh as roadmap.
