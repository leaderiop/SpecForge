EnginePool is well-tested bookkeeping for engines that do not exist — every call still pays a fresh Wasmtime compile inside instantiate. The LRU/eviction/memory-ceiling logic is correct and thread-safe, so this is less a rewrite than a promotion: store real instantiated plugin handles instead of {name, memory_mb} structs. For an LSP/MCP story (which is the whole pitch for warm engines), measure cold vs warm handshake+describe before and after so the README number is real.

README promises warm engines for LSP/MCP latency, but EnginePool is bookkeeping only: WarmInstance is a {name, memory_mb} struct pushed into a VecDeque — no Plugin, no Module, no engine. Every actual call goes through ExtismRuntime::instantiate, which builds a fresh Plugin from raw bytes (full Wasmtime compile + instantiate) before each handshake/describe exchange, so LSP completions pay cold-start cost every time. The pool's eviction logic and memory ceiling are carefully tested against entries that correspond to nothing in memory. Fix: make the pool hold real instantiated Plugins (or serialized Modules) per extension, hand them out to the runtime, and measure cold vs warm handshake+describe so the README claim is backed by numbers.

use std::sync::Arc;

/// A warm engine entry backed by a real instantiated plugin handle.
pub struct WarmInstance {
    pub extension_name: String,
    pub memory_mb: u32,
    pub plugin: Arc<wasmtime::Instance>,
}

impl EnginePool {
    /// Take a warm instance for immediate use; the caller returns it via
    /// `restore` so LRU recency reflects real usage, not bookkeeping.
    pub fn checkout(&self, extension_name: &str) -> Option<Arc<wasmtime::Instance>> {
        let mut instances = self.instances.lock().expect("EnginePool lock poisoned");
        let idx = instances.iter().position(|i| i.extension_name == extension_name)?;
        let entry = instances.remove(idx)?;
        instances.push_back(entry); // refresh LRU position
        Some(Arc::clone(&instances.back().unwrap().plugin))
    }
}
