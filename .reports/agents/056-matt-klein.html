The same 'extension' concept has three parallel implementations: the native BuiltinExtension trait (specforge-wasm/builtin.rs), the four embedded Wasm blobs loaded via extism builtins.rs, and a third native-Rust set in specforge-emitter's builtins/mod.rs (RustExtension, TypeScriptExtension — names absent from the shipped Wasm four). They are already drifting: emitter KNOWN_BUILTINS lists six names while docs/extension-inventory.md describes five extensions and only four .wasm modules ship, and CompositeRuntime's builtin-first dispatch (C7-06) decides which implementation actually serves a request with no diagnostic. Every protocol fix must now be applied in three places and verified three ways. Collapse to one execution path — builtins are exactly the four embedded .wasm modules speaking the Wasm protocol — and generate the inventory doc from the live registry so drift becomes impossible.
