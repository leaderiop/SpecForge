Auditor review

Yank is the best decision in this subsystem — flag in the index, blob kept on disk, clean split — the right skeleton for unyank and ownership. The write path needs the same care: racers overwrite blobs, failed inserts orphan files, and slash-to-underscore flattening collides distinct packages. Hash-namespace the dirs, write once, verify sha256 at download.

after — proposed fix
    fn package_dir(&self, name: &str) -> PathBuf {
        let mut h = DefaultHasher::new();
        name.hash(&mut h);
        self.base_dir.join(format!("{:016x}", h.finish()))
    }

    pub fn store_wasm_new(&self, name: &str, version: &str, data: &[u8]) -> Result<(), String> {
        std::fs::create_dir_all(self.package_dir(name)).map_err(|e| e.to_string())?;
        let path = self.wasm_path(name, version);
        match std::fs::OpenOptions::new().write(true).create_new(true).open(&path) {
            Ok(mut f) => f.write_all(data).map_err(|e| e.to_string()),
            Err(e) if e.kind() == std::io::ErrorKind::AlreadyExists => Err("artifact immutable".into()),
            Err(e) => Err(e.to_string()),
        }
    }

Explain like I'm 10

Two packages whose names differ only by slash-vs-underscore get the same folder, and a failed labeling leaves an unlabeled box forever. The recall path does the right thing — hide from catalog, keep the box — like the big registries; tighten the write path.

Proposed solution. Delete blob on insert failure; create-new semantics for wasm files; namespace storage by hashed id or real subdirectories; verify sha256 on download.
