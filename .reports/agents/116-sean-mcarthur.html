Hand-rolled urlencoded() leaves ampersand, question mark, hash, percent unescaped - search queries can corrupt or inject URL params

highC14-00
116 Sean McArthureffort Smoves: HTTP client correctness
Evidencecrates/specforge-registry/src/client/http_client.rs:371,404-407 — search builds the URL by hand; urlencoded() only replaces space, @ and slash. A query containing ampersand or hash truncates or reroutes the query string; percent yields an invalid escape.

HttpRegistryClient::search (crates/specforge-registry/src/client/http_client.rs) builds the query URL with format!("{}/search?q={}&limit=50", base, urlencoded(query)) and urlencoded() only replaces space, @ and slash. A query containing & silently becomes an extra parameter (or truncates the q value), ? and # truncate the query string entirely, and a bare % produces an invalid percent-escape the server may reject. Because this is the client AI agents call for extension discovery, any free-form search term can corrupt the request. The fix is form_urlencoded/url::Url query_pairs_mut, which percent-encodes every reserved byte.

RateLimited retry_after_ms hardcoded to 5000; Retry-After header ignored

mediumC14-01
116 Sean McArthureffort Smoves: Hardcoded retry sites (4 to 0)
Evidencecrates/specforge-registry/src/client/http_client.rs:110-112,168-170,262-264 — All 429 arms construct RateLimited with retry_after_ms 5000; resp.headers() is never consulted, so server-provided Retry-After is discarded.

All three 429 arms in http_client.rs (fetch_versions ~line 110, fetch ~line 168, search ~line 262) construct RegistryError::RateLimited { retry_after_ms: 5000 } with the same hardcoded constant, and resp.headers() is never consulted. A registry that returns Retry-After: 120 is therefore retried every 5 seconds by watch-mode or batch resolvers, guaranteeing a hammering loop until the window expires. A single helper reading Retry-After (delta-seconds or HTTP-date) with a 5000 ms fallback removes the duplication across the arms and respects the server contract.

/// Honor the server-provided Retry-After (delta-seconds or HTTP-date);
/// fall back to 5s when the header is absent or unparseable.
fn retry_after_ms(resp: &reqwest::blocking::Response) -> u64 {
    resp.headers()
        .get(reqwest::header::RETRY_AFTER)
        .and_then(|v| v.to_str().ok())
        .and_then(|s| s.trim().parse::<u64>().ok())
        .map_or(5_000, |secs| secs.saturating_mul(1_000))
}
