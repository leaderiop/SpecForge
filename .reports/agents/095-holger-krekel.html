Holger Krekel: the collect command is a mail office that announces the truck and never opens the envelope - ingest_collector_report sits exported in specforge-wasm with no caller, and the documented --from-junit flag is a fiction the vision doc tells CI users. Coming from pytest, capture durability is my other worry: results live in a static queue until libc::atexit, so one CI timeout or panic=abort wipes the whole run. Wire collect first; then append per-test to a jsonl so a crashed run still reports the tests that finished.

pub fn run(path: &Path, collector: Option<&str>, format: &str, from_junit: Option<&Path>) -> i32 {
    let Some(project_root) = find_project_root(path) else {
        eprintln!("error: no specforge project found");
        return 1;
    };

    let junit = from_junit.unwrap_or_else(|| Path::new("target/nextest/ci/junit.xml"));
    let xml = match std::fs::read_to_string(junit) {
        Ok(xml) => xml,
        Err(e) => {
            eprintln!("error: cannot read junit report {}: {e}", junit.display());
            return 1;
        }
    };

    match ingest_collector_report(collector.unwrap_or("rust"), &xml) {
        Ok(report) => {
            let out = project_root.join("target/specforge/specforge-report.json");
            match std::fs::write(&out, serde_json::to_string_pretty(&report).unwrap()) {
                Ok(()) => println!("collected {} results -> {}", report.entries.len(), out.display()),
                Err(e) => eprintln!("error: write failed: {e}"),
            }
            0
        }
        Err(diag) => {
            eprintln!("{}: {}", diag.code, diag.message);
            1
        }
    }
}

Evidenceatexit.rs:12-21registry.rs:33-46

All results accumulate in a process-global SegQueue<TestRecordEntry> (registry.rs:33) materialized only by an extern C handler installed via unsafe libc::atexit (atexit.rs:12-21). Any abnormal exit - panic=abort, SIGKILL from a CI timeout, nextest killing a hung test, a segfault - skips atexit and every record is lost: a run that crashed midway reports zero results, and nothing can tail progress mid-run. The drop_over_catch_unwind decision is sound but the durability gap is not; appending one JSON line per test to a per-binary jsonl from the guard's Drop makes capture crash-safe while atexit merely finalizes.

impl TestGuard {
    fn flush(&self, outcome: TestOutcome) {
        let entry = TestRecordEntry {
            entity_kind: self.entity_kind.to_string(),
            entity_id: self.entity_id.to_string(),
            test_name: self.test_name.to_string(),
            file: self.file.to_string(),
            verify: self.verify.map(|s| s.to_string()),
            outcome,
        };
        if let Ok(mut log) = result_log() {
            // Append immediately: crash-safe even under panic=abort or SIGKILL.
            let _ = writeln!(log, "{}", serde_json::to_string(&entry).unwrap_or_default());
            let _ = log.flush();
        }
    }
}

impl Drop for TestGuard {
    fn drop(&mut self) {
        let outcome = if std::thread::panicking() {
            TestOutcome::Fail
        } else {
            TestOutcome::Pass
        };
        self.flush(outcome);
    }
}
