Journey flows in spec/product/journeys.spec are numbered free-form strings ('1. Developer runs specforge init in an empty directory ...'), referencing no behavior or event IDs, so journeys cannot be pulled: clicking a step does not light up the behavior and event that carry it, and per-step verify coverage is impossible. ADR pe_journey_flow_opaque (spec/extensions/product/decisions.spec:469-495) accepts this explicitly, which makes it a documented limitation rather than an accident — but the project simultaneously markets journeys as traceability. Either drop the traceability claim or add an optional structured steps field of step plus behavior-or-event references alongside the prose.

Explain like I'm 10

The blueprint drawing shows each user step as a handwritten sentence instead of a wire that plugs into the actual machine parts. You can read the story, but you can't pull a thread: clicking a step should light up the behavior and event that carry it. Today the thread isn't attached.

Proposed solution. Either accept opacity permanently (and stop calling journeys traceability) or add an optional structured steps field: [{step, behavior|event}] alongside the prose, validated as references; journeys then become executable slices with verify coverage per step.
